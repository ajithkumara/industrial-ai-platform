# Disaster Recovery

Answers one question: **"What happens if the Azure subscription disappears?"**
(As it did on 2026-08-26 when the dev subscription expired.)

## The short answer

The platform is **reconstructable from Git** into any new subscription using
the [Fresh-Environment Rebuild Procedure](deployment.md#fresh-environment-rebuild-procedure).
What is *not* in Git — secrets, Terraform state, data, model artifacts — is
either regenerable or must be backed up separately, as detailed below.

## Four distinct backup categories

Do not conflate these — they have different owners and recovery paths.

| Category | What | Where it lives | Recovery |
|----------|------|----------------|----------|
| **SOURCE backup** | all code, Terraform, DAB, notebooks, config | **Git (GitHub)** | `git clone` — always current |
| **STATE backup** | Terraform state | Azure Storage remote backend (`rg-terraform`) | dies with the subscription; see below |
| **SECRET backup** | connection strings, tokens | `.env` (gitignored), Azure Key Vault | re-generated by `terraform apply` (new resources = new keys) |
| **DATA backup** | telemetry, Bronze/Silver/Gold tables | ADLS Gen2 | re-ingestible (CWRU is public); export if you need history |
| **MODEL backup** | trained models + thresholds | MLflow / Unity Catalog `industrial_ai.ml` | re-trainable deterministically (`random_seed=42`) |

## What is reproducible vs what must be recreated

**Fully reproducible from Git (no backup needed):**
- All Azure infrastructure (Terraform).
- All Databricks workloads (DAB).
- Unity Catalog structure incl. the `ml` schema.
- The ML models — retraining on the committed CWRU data with `random_seed=42`
  is deterministic and reproduces the reported metrics.

**Must be recreated / re-supplied (MANUAL):**
- **Secrets** — regenerated automatically when Terraform creates new resources;
  re-populate `.env` from `terraform output` (see deployment §4).
- **Terraform state** — a new subscription starts with fresh state. If the old
  subscription is already disabled you cannot read its remote state; this is
  fine because you are rebuilding, not importing. Just `terraform init` the new
  backend and `apply`.
- **Historical runtime data** — if you need the *old* telemetry/tables, they
  must have been exported before the subscription expired (see
  `scripts/backup_before_subscription_expiry.ps1`). Otherwise re-ingest.

## Subscription-expiry runbook (observed 2026-08)

When a subscription expires it becomes **read-only** — you cannot delete or
modify resources, and `terraform destroy` / `az group delete` fail with
`ReadOnlyDisabledSubscription`. This is expected and safe:

1. A disabled subscription **incurs no charges**; Azure auto-deprovisions
   resources after its retention window.
2. Verify zero balance in **Cost Management + Billing → Invoices**.
3. Do **not** click *Upgrade* (converts a free/credit account to paid).
4. Rebuild in the new subscription via the Fresh-Environment Rebuild Procedure.

## Pre-expiry backup (optional history preservation)

`scripts/backup_before_subscription_expiry.ps1` captures `.env`, Terraform
state, MLflow artifacts, and ADLS data to local disk. Run it **before** a
subscription expires if you want historical data/state; it is not required for
a clean rebuild (source + deterministic retraining cover that).

## Recovery time

A full rebuild (bootstrap → apply → bundle deploy → re-ingest → retrain) is
approximately **30–45 minutes**, dominated by Databricks workspace creation.
